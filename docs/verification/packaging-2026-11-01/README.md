# Package and container verification

The isolated build produced `clink_mcp_server-0.1.0.tar.gz` and `clink_mcp_server-0.1.0-py3-none-any.whl`. `artifacts.json` records their hashes and resource checks. Artifacts and disposable environments are retained in the durable, ignored repository path `test_output/package_check/`. The build uses setuptools 84.2.1 and wheel 0.48.0; the declared backend floor is setuptools 77 for modern SPDX license metadata.

`fresh-runtime.json` records the installed wheel in a newly created Python 3.12.15 environment with only the declared dependencies and transitives. No `openai`, `google` or `providers` package was importable. The MCP client launched the installed `clink-mcp-server` entrypoint from an unrelated synthetic working directory with an empty synthetic HOME, no provider credentials, no installed CLI on PATH, and the existing network-denying Seatbelt profile. A connection-denial preflight established that network access was blocked. Initialization, 18 schemas, six local tools and a structured `cli_missing` advisory error passed. The exact installed dependency versions are in the receipt. Python 3.10/3.11 are declared/CI-targeted but were not executed in this pass.

`docker-runtime.json` records an actual locally built Linux arm64 Python 3.12 image and MCP stdio session, with networking disabled, a read-only filesystem, a non-root user, no credential mounts and no CLI installation. All 18 schemas, the same six local tools, missing-CLI handling and the offline health check passed. This does not verify any native CLI or authentication in containers. The image and package builds are local only; no registry publishing, deployment or GitHub workflow was triggered.

`focused-unit.xml` and `focused-unit.txt` record 33 passing replacement tests. The baseline's 85 Docker, 18 deploy and 16 uvx tests included provider-key assumptions, fabricated performance/readiness numbers, mocked calls that never executed helpers and tautological assertions. The replacements execute the actual health-check functions and shell helpers against a recording executable, check stdio/quoting/error propagation, and inspect actual configuration and package resources. `checks.txt` records check-only Ruff, Black and isort; shell syntax checks also passed.

Earlier verification attempts remain disclosed: the first non-escalated package build could not resolve PyPI because network access was restricted; the first sandbox smoke could not nest Seatbelt under the tool sandbox. Authorized escalated runs resolved those environment restrictions. An initial disposable smoke harness had a variable-shadowing error before launch. Its first launched MCP run then correctly rejected incomplete docgen test arguments; schema-valid docgen/tracer fixtures resolved that harness defect. No production fallback or weakened policy was introduced. The deprecated license-table warning from the first build was removed by using SPDX metadata and a compatible setuptools floor.

These artifacts pin a work-in-progress source snapshot. Rebuild and refresh the receipts after the conductor's final source freeze before treating them as final-release evidence.
