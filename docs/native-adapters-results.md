## Implemented contracts

| Adapter | Input and private continuation | Native outcome handling |
| --- | --- | --- |
| xAI Grok Build | A closed `0600` prompt file in a private `0700` directory; exact UUID resume. The file lives through queueing and process cleanup. | Structured terminal JSON and the installed headless permission-refusal diagnostic, including refusal with exit zero. |
| Antigravity | One bounded user-message NDJSON object on stdin, followed by EOF; exact conversation resume. | Structured terminal status, denied actions, incomplete/timeout reasons, and recoverable tool errors. |
| Codex | Task text on stdin through `exec`; exact thread resume. | Typed JSONL lifecycle, recoverable tool failures, and a conservative set of version-pinned native permission diagnostics. Generic `declined` is not sufficient to identify a permission refusal. |

All use the existing task handles, attempt tracking, request-key deduplication, project ownership, deadline, process pool, cancellation, and private session mapping. Native launch does not suppress configured hooks, MCP integrations, skills, or subagents. The CLI's own headless behavior and permissions still apply. No approval bypass, interactive relay, automatic retry, fallback, or persistent task store was added.

## Reproduction and limits

Inspect the verifier's options before a deliberate live run:

```sh
.venv/bin/python scripts/verify_native_adapters.py --help
```

The helper requires explicit `--live`, a selected adapter, and a new evidence path under `docs/verification`. `--prepare-only` performs no model submission. Keep prior receipts and pass `--prior-evidence` when continuing an investigation; repeated checks require explicit `--replace-check`. Additional allowances are bounded and must follow diagnosis, never reset consumed attempts.

Risk & Mitigation: native execution can have partial effects before refusal, timeout, or cancellation. Verification uses standalone disposable projects and immutable fixture bindings, rechecked before independent host tests and after shutdown. Cleanup proves only the observed process group and identified synthetic descendants; detached or remote work may survive. Temporary Grok/Codex trust cleanup removes only unchanged grants created by the helper. Codex writes use fresh native versions and compare unrelated semantic state, but do not provide an interprocess lock or restore a complete configuration snapshot. Authentication remains owned by the native CLI.

Execution and investigation agents were explicitly selected as Sol 6.1/ultra, planning as Astra/ultra, and independent review as Sol 6.1/high. Effective runtime model metadata was unavailable and remains unverified.
